================================================================================
RUBISCO-EPYC1 DIFFERENTIABLE BROWNIAN DYNAMICS (BD) WORKFLOW
================================================================================

This document describes the environment configuration, execution workflows,
and programmatic usage of the PyTorch-based, differentiable Brownian Dynamics
simulation operator (RubiscoEpyc1TimeStepper) for Rubisco-EPYC1 phase separation.

--------------------------------------------------------------------------------
1. ENVIRONMENT SETUP & DEPENDENCIES
--------------------------------------------------------------------------------

The simulation environment is specified in `environment.yml` (and `enviornment.yml`).
It incorporates PyTorch (>=2.1), HOOMD-blue with GPU support, GSD, and the NEFI
timestepping operator framework (CAB-Lab-Princeton/NEFI).

1.1 Create or Update the Conda Environment:
   # Create a fresh environment:
   conda env create -f environment.yml

   # Or update an existing environment:
   conda env update -f environment.yml --prune

   # Activate the environment:
   conda activate condenstate_ml

   Note on Platform Support:
   The conda-forge distribution of `hoomd=*=*gpu*` is officially supported on
   Linux (x86_64) and macOS (x86_64, arm64). For native Windows workstations,
   running within WSL2 (Windows Subsystem for Linux) with NVIDIA CUDA drivers
   or submitting to a Linux HPC cluster with GPU nodes is strongly recommended,
   as native win-64 builds for HOOMD GPU are not available on conda-forge.

1.2 Verify Dependencies and GPU Access:
   # Verify Python version (>=3.11):
   python --version

   # Verify PyTorch and CUDA availability:
   python -c "import torch; print(f'PyTorch {torch.__version__}, CUDA available: {torch.cuda.is_available()}')"

   # Verify NEFI installation:
   python -c "import nefi; from nefi.operators.timestepping import TimeStepper; print('NEFI TimeStepper available')"

   # Check available GPU devices:
   nvidia-smi

2. SYSTEM ARCHITECTURE & PHYSICAL MODEL
--------------------------------------------------------------------------------

The simulation replicates the physical topology of simulate_hoomd_patchy_full.py:
  * Total particles: 792
    - 24 Rubisco cores (Type 'R', mass=1.0, mobility=0.2)
    - 192 Rubisco surface patches (Type 'P', 8 patches per Rubisco at normalized
      cube vertices [+/-1, +/-1, +/-1]/sqrt(3), tethered with k=50.0, r0=2.5)
    - 288 EPYC1 spacers (Type 'S', mobility=1.0)
    - 288 EPYC1 stickers (Type 'T', mobility=1.0)
    - 48 total EPYC1 chains of 12 beads alternating [S, T, S, T, S, T, S, T, S, T, S, T]
      tethered with backbone bonds (k=10.0, r0=1.2). Total bonds = 720.
  * Bounded Gaussian Sterics:
    Repulsive Gaussian pairs across R-R, S-S, T-T, S-T, R-S, R-T, P-P, P-S, P-R.
  * Continuous Gaussian Attraction:
    Attractive Gaussian potential on sticker-patch (T-P) pairs with epsilon = -|KON|
    (or -|EPS|), sigma = 1.0, and r_cut = 3.0.
  * Integrator:
    Euler-Maruyama Brownian Dynamics with thermal noise amplitude sqrt(2 * mu * kBT * dt)
    with kBT = 1.0 and minimum-image periodic boundary wrapping.
  * Differentiability:
    All force evaluations and Euler-Maruyama updates are implemented via vectorized
    PyTorch tensor operations subclassing NEFI TimeStepper with block checkpointing
    (grad_mode="checkpoint"), enabling exact adjoint backpropagation.

3. RUNNING SIMULATION SWEEPS VIA CLI (torch_kf_bd_kf_sweep.py)
--------------------------------------------------------------------------------

The script `torch_kf_bd_kf_sweep.py` supports JSON parameter files, inline JSON
strings, and process substitution.

3.1 Run All Conditions from params.json:
   # Sequentially executes all conditions defined in params.json
   cd rubisco_epyc1_nucleation_growth/torch_sim
   python torch_kf_bd_kf_sweep.py params.json

3.2 Run a Single Condition via Inline JSON String:
   # Linux / macOS / Bash:
   python torch_kf_bd_kf_sweep.py '{"name": "test_run", "BOX": 35.0, "EPS": 1.2, "N_STEPS": 50000, "WRITE_EVERY": 500, "SEED": 42}'

   # Windows PowerShell (escape inner double quotes with backslashes):
   python torch_kf_bd_kf_sweep.py '{\"name\": \"test_run\", \"BOX\": 35.0, \"EPS\": 1.2, \"N_STEPS\": 50000, \"WRITE_EVERY\": 500, \"SEED\": 42}'

3.3 Run via Bash Process Substitution:
   python torch_kf_bd_kf_sweep.py <(echo '{"name": "coarsening", "BOX": 29.0, "EPS": 2.5, "N_STEPS": 100000, "WRITE_EVERY": 500, "SEED": 105}')

3.4 Background Execution with nohup:
   nohup python torch_kf_bd_kf_sweep.py params.json > bd_kf_sweep.log 2>&1 &
   tail -f bd_kf_sweep.log

3.5 Multi-GPU Parallel Sweep (Bash):
   # Create output directories before running background redirections:
   mkdir -p data_bd traj_bd plots_bd

   # Dispatch conditions across multiple GPUs concurrently
   GPU_COUNT=$(nvidia-smi --query-gpu=count --format=csv,noheader | head -n 1)
   idx=0
   jq -c '.[]' params.json | while read -r row; do
       gpu_id=$(( idx % GPU_COUNT ))
       echo "Dispatching condition on GPU ${gpu_id}: ${row}"
       CUDA_VISIBLE_DEVICES=${gpu_id} python torch_kf_bd_kf_sweep.py <(echo "${row}") > "data_bd/run_${idx}.log" 2>&1 &
       idx=$(( idx + 1 ))
   done
   wait
   echo "All sweep conditions completed."

3.6 Multi-Process Parallel Sweep (Python):
   # Ensure output directories exist:
   mkdir -p data_bd traj_bd plots_bd

   # Option A: Standalone runner script (cross-platform, spawn-safe):
   # Guard execution with `if __name__ == "__main__":` inside a script (e.g. run_parallel_sweep.py)
   # to support multiprocessing spawn mode on Windows and macOS:
   """
   import json
   import subprocess
   from concurrent.futures import ProcessPoolExecutor

   def run_condition(cond: dict) -> None:
       cmd = ["python", "torch_kf_bd_kf_sweep.py", json.dumps(cond)]
       subprocess.run(cmd, check=True)

   def main() -> None:
       with open("params.json", "r") as f:
           conditions = json.load(f)
       with ProcessPoolExecutor(max_workers=4) as executor:
           list(executor.map(run_condition, conditions))

   if __name__ == "__main__":
       main()
   """
   python run_parallel_sweep.py

   # Option B: Inline execution via ThreadPoolExecutor (cross-platform):
   # (Because worker tasks launch independent subprocesses, ThreadPoolExecutor
   # avoids multiprocessing spawn/pickling restrictions on Windows and macOS):
   python -c "import json, subprocess; from concurrent.futures import ThreadPoolExecutor; conditions = json.load(open('params.json')); list(ThreadPoolExecutor(max_workers=4).map(lambda c: subprocess.run(['python', 'torch_kf_bd_kf_sweep.py', json.dumps(c)], check=True), conditions))"

4. PROGRAMMATIC PYTORCH / NEFI USAGE EXAMPLE
--------------------------------------------------------------------------------

The following example demonstrates how to import `RubiscoEpyc1TimeStepper`,
execute a forward rollout, compute differentiable soft contacts, and compute
gradients with respect to physical interaction parameters (e.g., epsilon)
using NEFI's checkpointed adjoint time-stepper.

```python
from typing import Any
import torch
from torch_kf_bd_kf_sweep import (
    RubiscoEpyc1TimeStepper,
    compute_soft_contacts,
)

def compute_differentiable_trajectory_loss(
    trajectoryPositions: torch.Tensor,
    box: float,
    cutoff: float = 3.0,
    tau: float = 0.1,
    targetContacts: float = 300.0,
) -> torch.Tensor:
    """Compute differentiable squared error loss between soft contacts and target."""
    finalFramePositions = trajectoryPositions[-1]
    softContactMatrix = compute_soft_contacts(
        finalFramePositions,
        box=box,
        cutoff=cutoff,
        tau=tau,
    )
    totalSoftContacts = softContactMatrix.sum()
    targetTensor = torch.tensor(
        targetContacts,
        dtype=trajectoryPositions.dtype,
        device=trajectoryPositions.device,
    )
    return (totalSoftContacts - targetTensor) ** 2

def execute_simulation_optimization_step(
    stepper: RubiscoEpyc1TimeStepper,
    paramsByField: dict[str, Any],
    epsilon: torch.Tensor,
    targetContacts: float = 300.0,
) -> dict[str, float]:
    """Execute forward simulation rollout, calculate loss, and evaluate gradients."""
    trajectoryPositions = stepper(paramsByField)
    loss = compute_differentiable_trajectory_loss(
        trajectoryPositions=trajectoryPositions,
        box=float(paramsByField["box"]),
        targetContacts=targetContacts,
    )
    loss.backward()
    return {
        "loss": float(loss.item()),
        "epsilonGrad": float(epsilon.grad.item()),
    }

def run_differentiable_simulation_step(
    device: torch.device | None = None,
    initialEpsilon: float = 1.5,
) -> dict[str, float]:
    """Configure device and parameters, execute step, and display results."""
    targetDevice = device or torch.device("cuda" if torch.cuda.is_available() else "cpu")
    epsilon = torch.tensor(initialEpsilon, dtype=torch.float32, device=targetDevice, requires_grad=True)

    paramsByField: dict[str, Any] = {
        "name": "differentiable_run",
        "box": 35.0,
        "kon_or_epsilon": epsilon,
        "n_steps": 2000,
        "write_every": 100,
        "dt": 0.0005,
        "seed": 42,
    }

    stepper = RubiscoEpyc1TimeStepper(
        grad_mode="checkpoint",
        checkpoint_every=32,
        device=targetDevice,
    )

    metricsByName = execute_simulation_optimization_step(
        stepper=stepper,
        paramsByField=paramsByField,
        epsilon=epsilon,
    )

    print(f"Loss: {metricsByName['loss']:.4f}")
    print(f"Epsilon gradient (dLoss/dEpsilon): {metricsByName['epsilonGrad']:.6f}")
    return metricsByName

if __name__ == "__main__":
    run_differentiable_simulation_step()
```

5. OUTPUT ARTIFACTS & DATA SCHEMAS
--------------------------------------------------------------------------------

Each simulation execution produces four synchronized output artifacts:

5.1 Trajectory File: `traj_bd/{name}.xyz`
   - Extended XYZ format compatible with OVITO.
   - Per-atom columns: `type x y z`
   - Particle types:
       R: Rubisco center (mass=1.0, display radius=2.0)
       P: Rubisco surface patch (display radius=0.8)
       S: EPYC1 spacer bead (display radius=0.6)
       T: EPYC1 sticker bead (display radius=0.6)

5.2 Time Series Data: `data_bd/{name}.csv`
   - Schema matches HOOMD reference data exactly:
     frame, step, time, box, kon_or_epsilon, epsilon_used, koff_recorded, contacts, bonds, clusters, largest, fraction
   - Column descriptions:
       * frame: integer observation index (0, 1, 2, ...)
       * step: simulation integration step index (frame * write_every)
       * time: physical simulation time (step * dt)
       * box: cubic simulation box length
       * kon_or_epsilon: configured attraction parameter
       * epsilon_used: effective epsilon applied in force computation
       * koff_recorded: unbinding rate (0.0 for continuous potential)
       * contacts: total hard sticker-patch contacts within cutoff (3.0)
       * bonds: total active bonds
       * clusters: number of connected macromolecular clusters (Union-Find)
       * largest: particle count in the largest cluster
       * fraction: mass fraction in the largest cluster (largest / 72, matching the 24 Rubisco + 48 EPYC1 macromolecular units in simulate_hoomd_patchy_full.py)

5.3 Summary Statistics: `data_bd/{name}_summary.json`
   - High-level trajectory aggregates:
     * initial, final, mean, and standard deviation for contacts, clusters,
       largest cluster size, and cluster fraction.
     * simulation parameters and execution runtime metadata.

5.4 Diagnostic Visualizations: `plots_bd/{name}_{metric}.jpeg`
   - High-resolution trajectory time-series plots for:
     * `contacts`: Sticker-patch contact growth over time
     * `bonds`: Active bond count over time
     * `clusters`: Condensate cluster count evolution
     * `largest`: Largest cluster particle count
     * `fraction`: Largest cluster mass fraction

--------------------------------------------------------------------------------
6. VISUALIZATION IN OVITO
--------------------------------------------------------------------------------

To visualize the trajectory in OVITO:
1. Open OVITO and load `traj_bd/{name}.xyz`.
2. In the "Particle types" modifier:
   - Type R: Color = Dodger Blue, Radius = 2.0
   - Type P: Color = Orange, Radius = 0.8
   - Type S: Color = Gray, Radius = 0.6
   - Type T: Color = Crimson, Radius = 0.6
3. Add a "Simulation Cell" modifier to visualize periodic boundary conditions.
4. Scrub through the timeline or click play to observe condensate nucleation
   and phase coarsening.
